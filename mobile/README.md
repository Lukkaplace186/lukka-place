# Lukka Place app (Google Play + App Store)

Owner decisions 2026-11-10:
- **Why an app:** customers and agents get their alerts as phone notifications,
  because WhatsApp only reaches someone who wrote to us in the last 24 h unless
  a Meta template is approved.
- **One app for everyone.** Customers search listings in it; agents also get
  their agent space.
- **No browser-install path.** People in DRC do not add websites to their home
  screen.

**What the app is:** a Capacitor shell that opens `https://lukkaplace.com/app`
(`capacitor.config.json` → `server.url`). `web/app/app/route.js` then sends:
- a signed-in agent to `/compte/agent`;
- everyone else to the listings.

The site *is* the app, so every website deploy updates it without a store
release. A new store build is needed only when this folder changes (plugins,
icons, config).

**How alerts flow:**

1. **Registration.** In the agent space or the Espace Client,
   `web/components/AppPushBridge.js` asks for notification permission and gets
   this phone's Firebase (FCM) token. `POST /api/push/register` (with
   `as: agent|customer`) stores it in `push_devices`.
2. **Push and inbox.** The engine (`services/pushNotify.js`) pushes each alert
   to that person's phones first and records it in `notifications`, their
   in-app inbox:
   - agents: "Alertes"
   - customers: "Notifications"

   Customers can switch off kinds of alerts in Mon profil
   (`notification_preferences`).
3. **WhatsApp fallback.** An alert goes on WhatsApp at once when the person has
   no app, or the push was refused. An urgent alert still unread after a few
   minutes gets a late WhatsApp copy:
   - agents: 5 minutes (`PUSH_FALLBACK_MIN`)
   - customers: 10 minutes (`PUSH_CUSTOMER_FALLBACK_MIN`)
4. **Tapping.** A tap on a notification opens its inbox entry, which marks it
   read and redirects to the right page:
   - agents: `/compte/agent/alertes/<id>`
   - customers: `/compte/client/notifications/<id>`
5. **Logout** revokes this phone's token.

## One-time setup (owner)

1. **D-U-N-S number** for Lukka Place (free, 1–3 weeks). Both stores need it to
   register as an organisation.
2. **Google Play Console**: organisation account, $25 one-off.
3. **Apple Developer Program**: organisation account, $99 a year.
4. **Firebase project** "Lukka Place", with two apps:
   - **Android**, package `com.lukkaplace.app` → download `google-services.json`.
   - **iOS**, bundle id `com.lukkaplace.app` → download `GoogleService-Info.plist`.

   Then, in Firebase → Project settings → Cloud Messaging, upload the **APNs
   key** (.p8) from the Apple account.
5. **Service account for the engine**: Firebase → Project settings → Service
   accounts → "Generate new private key". Copy the JSON to the VPS, outside the
   repo, e.g. `/var/data/secrets/fcm-service-account.json`, `chmod 600`. Then set
   `FCM_SERVICE_ACCOUNT=/var/data/secrets/fcm-service-account.json` in the engine
   `.env` and run `pm2 restart lukka-place-engine --update-env`.

`com.lukkaplace.app` is permanent once published. Change it here **before**
the first upload if you want another id.

## Build

Requires Node 20+, and Android Studio for Android. iOS needs Xcode on a Mac,
or a cloud build (Codemagic, GitHub Actions macOS) — no Mac is needed to own the
app.

```bash
cd mobile
npm install
```

(`android/` and `ios/` are already generated; `npx cap add` is only for a
fresh checkout without them.)

Then:

1. **Firebase config files**:
   - Put `google-services.json` in `android/app/`.
   - Put `GoogleService-Info.plist` in `ios/App/App/` and add it to the target
     in Xcode.
2. **iOS capabilities** (Xcode → Signing & Capabilities): add **Push
   Notifications** and **Background Modes → Remote notifications**.
3. **Icons and splash**: from `web/public/brand/icon-square-512.png` (white
   logo on #144FC5), via `npx @capacitor/assets generate`.
4. Run `npx cap sync`, then build:
   - **Android**: `npm run build:android:release` (see "Release build" below).
   - **iOS**: `npx cap open ios` → Archive.

`android/` and `ios/` are generated by `npx cap add` and can be committed once
they exist (signing keys never are).

## Release build (Google Play)

`android/` exists (generated 2026-11-10 with Capacitor 8.6). On Windows,
Gradle 8.14 needs **JDK 21** (Android Studio's own Java 25 is too new):
`JAVA_HOME=%LOCALAPPDATA%\Programs\Java\jdk-21.0.13+9`.

- **The upload key** is `%USERPROFILE%\lukka-app-keys\lukka-upload.jks`
  (alias `lukka-upload`, made 2026-11-11, valid 30 years), with its password in
  `keystore.properties` beside it. Copy that file to `android/keystore.properties`
  (git-ignored) and `npm run build:android:release` signs the bundle;
  without it the release bundle is unsigned. **Back the folder up** (a USB key
  and a password manager): Google Play App Signing keeps the real app key, so a
  lost upload key can be reset through Play support, but that takes days.
  Upload-key SHA-256: `FF:7A:A3:62:FD:69:7A:7C:02:66:D4:2F:9E:94:47:F2:D0:4C:87:FD:40:F0:B0:F8:73:D8:3E:47:3D:DA:85:92`.
- **Output**: `android/app/build/outputs/bundle/release/app-release.aab`.
  Raise `versionCode` in `android/app/build.gradle` for every upload (Play
  refuses a number it has seen); `versionName` is what people see.
- **Test build without the stores**: `npm run build:android:debug` gives an
  APK (`android/app/build/outputs/apk/debug/app-debug.apk`) for a phone or the
  emulator (`adb install -r …`).

## iPhone build (needs a Mac or a cloud Mac)

`ios/` exists (generated 2026-11-11, Swift Package Manager, no CocoaPods).
Already done here: `Info.plist` (French, background push, camera and photo
wording, no export-encryption question), icons and splash, and
`AppDelegate.swift` forwarding the push token through Firebase. On the Mac:

1. `npm install && npx cap sync ios`, then `npx cap open ios`.
2. **Firebase package**: File → Add Package Dependencies →
   `https://github.com/firebase/firebase-ios-sdk`, add **FirebaseMessaging**
   to the App target. Required: the engine sends through FCM, and without it
   the phone registers Apple's raw token and no push arrives (the code is
   behind `#if canImport`, so it builds either way — check the token in
   `push_devices` is a long FCM token, not 64 hex characters).
3. Drag `GoogleService-Info.plist` (git-ignored, from the owner's Downloads)
   into the App target.
4. Signing & Capabilities: the team, **Push Notifications**, **Background
   Modes → Remote notifications**.
5. In Firebase → Project settings → Cloud Messaging → Apple app: upload the
   APNs key (.p8) from the Apple developer account.
6. Product → Archive → upload to App Store Connect / TestFlight.

## Store review notes

- **Apple 4.2 (minimum functionality)**: the app is more than a website in a
  frame. It has native push notifications for new requests and visits, the
  camera and photo picker for listing photos (the WebView's file picker), the
  native share sheet, and an offline screen (`www/offline.html`).
- **Apple 5.1.1(v) / Google Play account deletion**: accounts can be created
  in the app, so they can be deleted in it — customers: Espace client › Mon
  profil › Supprimer mon compte; agents: Paramètres › Supprimer mon compte
  (2026-11-11: the account is deleted, its listings archived without a name).
  Play also asks for a deletion web link: `https://lukkaplace.com/confidentialite#suppression`.
- **Privacy**: privacy-policy URL `https://lukkaplace.com/confidentialite`
  (app and notification sections added 2026-11-11). The app collects the
  phone number, name, listing photos, and a device token for notifications;
  no location, no contacts.
- **Test account**: give reviewers a test agent login (phone + password).

## Testing a push before the stores

Use the Play **internal testing** track and **TestFlight**. Install, log in as a
test agent, allow notifications, then create a viewing request on that agent's
test listing:

- The notification arrives with the app closed.
- A tap opens the request.
- With data off, the WhatsApp copy follows after `PUSH_FALLBACK_MIN` minutes.
